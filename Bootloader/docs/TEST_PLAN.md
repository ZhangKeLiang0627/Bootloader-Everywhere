# Bootloader 测试方案

面向「不变砖」这个第一优先级目标设计。按风险从高到低排列，
**第 4、5 项是核心**——其余测试通过都不能算数，必须过了这两关。

---

## 0. 测试环境

| 项 | 内容 |
|---|---|
| 目标板 | STM32F405RGT6 板卡 |
| 烧写器 | DAPLink（CMSIS-DAP，`0d28:0204`） |
| 串口 | USART1 / PA9 / PA10，115200 8N1，USB-TTL |
| 上位机 | SecureCRT / Xshell（YMODEM 发送）；后期用自研网页上位机 |
| 辅助脚本 | `tools/measure_rom.py`（ROM 复测） |
| 固件格式 | 裸 `.bin`，**文件名建议带版本**如 `lumos_app_v1.2.3.bin` |

### 测试用的 APP 固件集

需要提前准备这几个，后面反复用到：

| 名称 | 说明 |
|---|---|
| `app_good.bin` | 正常可运行的 APP（能点亮 LED / 串口输出即可） |
| `app_crash.bin` | **上电即 HardFault** 的 APP（用于回滚测试） |
| `app_large.bin` | 接近 APP 区上限（约 880KB）的固件 |
| `app_tiny.bin` | 极小固件（1-2KB） |
| `app_bad_crc.bin` | 传输过程中人为损坏的固件（用上位机改一个字节） |

> `app_crash.bin` 的做法：在 APP 的 `main()` 开头直接触发一个
> 未定义指令或除零异常，使其无论如何都进不了正常的自检确认。

## 1. 冒烟测试（首次上电）

| # | 步骤 | 预期 |
|---|---|---|
| 1.1 | 用 DAPLink 烧入 bootloader | 烧写成功，`Verified OK` |
| 1.2 | 打开串口（115200） | 看到 `===== LUMOS-bootloader =====` banner |
| 1.3 | 观察 banner 内容 | 打印 boot/app/meta 三个区域的地址与大小，均与 `bl_config.h` 一致 |
| 1.4 | 观察启动决策输出 | 首次烧写时 `meta` 应为 `INVALID`，决策为 `IAP` |
| 1.5 | 等待 | 串口持续输出 `waiting for YMODEM transfer...` |

**判据**：banner 与决策输出正确，无 HardFault、无重启循环。

## 2. 基础功能测试

| # | 步骤 | 预期 |
|---|---|---|
| 2.1 | 用 SecureCRT 发送 YMODEM，选 `app_good.bin` | 传输完成后串口打印 `outcome=DONE` 与 CRC32，随后自动重启 |
| 2.2 | 观察重启后输出 | `meta` 状态为 `TESTING`，`attempt 1/3`，随即跳转 APP |
| 2.3 | 确认 APP 运行 | APP 的 LED / 串口输出正常 |
| 2.4 | 复位一次 | 状态仍为 `TESTING`，`attempt 2/3`（说明计数在递增） |
| 2.5 | APP 自检后调用确认接口 | 状态转为 `VALID`，计数归零 |
| 2.6 | 再复位一次 | 状态 `VALID`，**直接跳转、不再打印 attempt**（正常启动零写入） |

**判据**：全流程符合预期，且第 2.6 步验证了「已确认固件启动时不写配置区」这一优化生效。

> 注意：当前 APP 侧尚未实现确认钩子（`LUMOS-app` 待建），
> 因此 2.5 之前会一直停在 `TESTING` 并在第 3 次启动后回滚。
> 联调阶段可临时把 `BL_BOOT_MAX_ATTEMPTS` 调大，或先做 APP 侧钩子。

## 4. 【核心】断电暴力测试

**目的**：验证「任意时刻断电都不变砖」。
这是整个设计的立足点，必须逐点验证，不能只靠推理。

### 4.1 断电时机矩阵

用继电器/开关或直接拔电源，在下列时机各断 3 次（共 18 次）：

| # | 断电时机 | 触发方式 | 预期上电后 |
|---|---|---|---|
| 4.1.1 | 刚发完首包、擦除**之前** | 看到串口开始输出后立刻断电 | 进 IAP（状态已置 Download） |
| 4.1.2 | 擦除**进行中**（S4 64KB 或 S5+ 128KB 擦除约 1 秒） | 在擦除窗口内断电 | 进 IAP，可重刷 |
| 4.1.3 | 数据传输**进行中**（约 50% 处） | 传输途中断电 | 进 IAP，可重刷 |
| 4.1.4 | 数据传完、CRC 校验阶段 | 进度到 100% 附近断电 | 进 IAP，可重刷 |
| 4.1.5 | 已 `commit`（状态已写 Testing）、跳转前 | 看到 `outcome=DONE` 后立刻断电 | 状态为 Testing，正常跳转或按计数回滚 |

**判据（每一条都必须满足）**：
1. 上电后**能进入 IAP**（串口有 banner，出现 `waiting for YMODEM transfer...`）
2. `meta` 状态打印清晰可辨，且**绝不会**出现「状态 Valid 但 APP 是空片」
3. 能够**重新刷入**并正常启动

### 4.2 配置区擦除窗口的极端情况

配置区槽位写满 2048 次后会触发扇区擦除（约 1 秒）。
该窗口内断电会导致配置区全 `0xFF` → 判为 `INVALID` → 停在 IAP。

| # | 步骤 | 预期 |
|---|---|---|
| 4.2.1 | 用脚本把槽位快速写满，观察擦除发生 | 擦除后状态保持，槽位从 0 重新开始 |
| 4.2.2 | 在配置区擦除窗口内断电 | 上电后停在 IAP，可重刷（可用性下降但不是变砖） |

### 4.3 反复断电的累积效应

| # | 步骤 | 预期 |
|---|---|---|
| 4.3.1 | 连续做 30 次「开始升级 → 随机时刻断电」 | 每次都能恢复，无一次变砖 |
| 4.3.2 | 统计成功率 | 应为 30/30 |

## 5. 【核心】变砖恢复与回滚测试

| # | 步骤 | 预期 |
|---|---|---|
| 5.1 | 刷入 `app_crash.bin`（上电即崩） | 传输与校验均成功，状态置 `TESTING` |
| 5.2 | 观察第 1 次启动 | `attempt 1/3`，跳转后 APP 崩溃并复位 |
| 5.3 | 观察第 2、3 次启动 | `attempt 2/3`、`attempt 3/3` |
| 5.4 | 观察第 4 次启动 | `resolve: app never confirmed` → 状态置 `REVOKED` → 停在 IAP |
| 5.5 | 重新刷入 `app_good.bin` | 成功，恢复正常 |

**判据**：5.4 必须自动发生，无需人工干预。这是「坏固件自动回滚」的关键验证。

### 5.1 Backdoor 强制进入

| # | 步骤 | 预期 |
|---|---|---|
| 5.1.1 | 在 APP 正常运行时复位，并在 300ms 窗口内从串口发送 `0x7F` | 进入 IAP，打印 `backdoor triggered` |
| 5.1.2 | 不在窗口内发送 | 正常跳转 APP |
| 5.1.3 | 把 `BL_BACKDOOR_WINDOW_MS` 改为 0 后重测 | 窗口关闭，立即跳转 |

## 6. 协议异常测试

| # | 场景 | 构造方式 | 预期 |
|---|---|---|---|
| 6.1 | 传输中拔掉串口线 | 物理拔线 | 超时后发 CA，退回 IAP 等待 |
| 6.2 | 单帧 CRC 错误 | 用脚本篡改一帧的 CRC 字节 | 板子回 NAK，上位机重传该帧，最终成功 |
| 6.3 | 包序号错误 | 篡改序号字节 | 回 NAK 请求重传 |
| 6.4 | 序号与反码不匹配 | 篡改反码 | 该帧被丢弃，请求重传 |
| 6.5 | 中途发送 CAN CAN | 上位机主动取消 | 板子回 ACK，`outcome=ABORTED` |
| 6.6 | 发送 ABORT 字符（`'A'`） | 手动发 `0x41` | 板子回 CAN CAN，退回 IAP |
| 6.7 | 握手阶段无响应 | 只连串口不发文件 | 握手超时后放弃，回到等待 |
| 6.8 | 串口噪声 | 在等待期间乱发随机字节 | 不应误入升级，退出后仍正常 |

## 7. 边界与非法输入

| # | 场景 | 预期 |
|---|---|---|
| 7.1 | 固件大小 = APP 区上限（880KB） | 接受 |
| 7.2 | 固件大小 = 上限 + 1 | 拒绝，回 CAN，打印 `reject: size ... > app area` |
| 7.3 | 固件大小为 0 | 拒绝，打印 `reject: zero size` |
| 7.4 | 文件名超长（>64 字符） | 截断处理，不越界、不崩溃 |
| 7.5 | 文件名无版本号 | 版本解析为 0，不影响升级 |
| 7.6 | 传输途中声明大小与实际不符（少了尾包） | 判为 `short file`，拒绝提交 |
| 7.7 | 写入的固件向量表非法（SP 不在 SRAM） | 提交前被 `verify_vector_table` 拦下 |

## 9. ROM 占用回归

每次改完代码都要做，避免不小心超 16KB：

```bash
python Bootloader/tools/measure_rom.py
```

| 配置 | 当前基线 | 阈值 |
|---|---|---|
| `-Oz` + 轻量日志（开发） | 14848 B | 不得超过 16384 B |
| `-Os` + 关日志（发布） | 12772 B | 建议留 2KB 以上余量 |
